## HTTP and recovery candidate — NO GO
No default fetch export, config change, secrets, routes, rate limiter, D1 or cloud resources created. Candidate requires explicit separate LAB_ONLY flag, D1_CANDIDATE plus trusted Access runtime and limiter binding. Six exact POST JSON routes. Read requests POST to keep a single strict browser contract; no mutation on receipt/queue/history. Strict HTTPS origin, no query parameters, Origin and Sec-Fetch-Site same-origin, custom X-Remura-CSRF header, no CORS/preflight, no client actor; fail closed if Safari does not supply required header. This browser CSRF control is not a secret token, does not protect against XSS/same-origin compromise or stolen Access credentials. No additional app cookie/session; Access one-hour session and durable revocation checked independently per operation. Test real Safari before release, no weakening silently. Front-end not connected. JSON max 4 KiB stream, reject inconsistent declared length, compression, invalid UTF-8, wrong shape; no request body or identity logging. Output JSON no-store, no CORS, generic errors. Must render user text safely in future UI.
 
Rate limit candidate: stable UUID HMAC key, one binding decision before DB and parsing; missing/error denies. Suggested 10 requests/60s per identity/location pending actual Free plan/evidence. Cloudflare limiter is approximate/local, not a strict global quota or guarantee of 500 invocations/day; invalid routes and requests denied before binding still consume Worker invocations; unauthenticated traffic must be blocked at dedicated Access perimeter. Need verified plan/availability, edge abuse policy, aggregate budget guard and hard D1 cap before activation. No new DO/cron/service. Docs 16/11 https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/ . Auth context fetched twice (limiter and adapter); real CPU/latency budget and binding metadata untested. Intake idempotency UUID per immutable subject; review/revocation guarded one-way transitions. Unknown writes never retried automatically; HTTP 409 not_confirmed is deliberately ambiguous, reconcile authoritative history/receipts under correct gate. Full operation nonce/expiry/replay policy for stale uncommitted mutations and recovery audit still required. No claim of complete replay prevention.

## Privacy, retention and restore policy proposal (not implemented)
Keep only data strictly needed: pseudonymous tags, slot, role, timestamps, source-level metadata. No email/UUID in clear, account balances, personal notes unrelated to levels, tokens, IP logging, screenshots or broker credentials. HMAC tags are personal data; decline unnecessary free text; explain purpose, access, retention and rights before invitation. Owner alone sees reasons. Provisional LAB retention proposal: review at 30 days, stop collection before 200 total entries or 8 MiB, whichever earlier; no automatic destructive deletion. Production retention duration, legal basis, deletion rights and lawful treatment of scientific history require owner decision. Append-only triggers forbid ordinary delete: separately authorized new empty archival generation or controlled rebuild with verified tombstones/deletion policy required, not ad hoc DROP or Time Travel. No real data while unresolved.

Restore is forbidden until independent privately held append-only revocation record and generation fence implemented and verified. Candidate sequence: close ingress + all operational flags; preserve current DB read-only if available; capture revocation watermark and encrypted independent journal outside restored snapshot, including owner revocation, identity tags, slot and time; verify exact backup target, integrity/schema and key custody; restore only to dedicated isolated generation with all gates forced closed independent of snapshot; compare inventory, replay tombstones without rebinding (including identifiers no longer in snapshot), reconcile history and ambiguous writes, validate FK and permissions. A missing journal, key, watermark, rollback marker, conflicting identities or unverified primary state is NO-GO. Never automatically activate based on restored gate flags. Owner break-glass remains privileged offline, explicit authorization, no public recovery bypass. Test real crash/concurrency/restore/revocation vs concurrent reads before user enrollment. Need independent journal implementation and quota/retention plan: this document is not a backup or proof that restore works. Preserve frozen scientific protocols; old approved levels remain historical, exclude revoked-source levels from new scientific admission pending explicit policy.
