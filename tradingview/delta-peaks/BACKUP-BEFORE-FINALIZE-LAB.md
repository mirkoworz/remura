## Backup-before-finalize synthetic transaction
A new isolated wrapper holds both cooperative private-directory locks; verifies exact current backup and checks free copy slot before reservation, writes authenticated encrypted candidate locally, verifies its joint state, copies the exact ciphertext into the second directory using exclusive temporary file, fsync, no-clobber link, directory fsync and readback, then finalizes the simulated pin. Status requires matching current backup. A failed backup or uncertain finalization means PENDING, not publication; old backup retained but not automatically admissible as current. At two-copy cap, a further cycle is refused before reservation. No deletion, rotation, automatic rollback or automatic reconciliation. Separate directories do not constitute independent storage failure domains. Cooperative locking and final fsync are not power-loss or remote durability evidence. Existing lower-level encrypted API can bypass this wrapper; no production caller or global admission enforcement. Six candidate regression tests; no real keys, data, external services or scientific promotion.
